# Introduction

In this project, we will build a **production-grade Blog Posts REST API** using **FastAPI**, **SQLAlchemy 2.0**, and **Pydantic v2**.

Unlike a basic CRUD application, this project follows a **layered architecture** that separates responsibilities into the **API**, **Service**, and **Repository** layers. This makes the application easier to understand, test, maintain, and extend as it grows.

Throughout the project, we will gradually transform a simple CRUD application into a production-ready backend by introducing industry-standard practices such as dependency injection, request and response models, exception handling, and database migrations.

## Learning Objectives

By the end of this project, you will learn how to:

- Configure SQLAlchemy with FastAPI
- Design a relational database
- Create SQLAlchemy models
- Create Pydantic models for API requests and responses
- Implement CRUD operations using the Repository pattern
- Organize business logic using the Service layer
- Apply Dependency Injection
- Design REST APIs using POST, GET, PUT, PATCH, and DELETE
- Validate requests and return structured responses
- Implement global exception handling
- Manage database schema changes using Alembic
- Deploy the application from SQLite to PostgreSQL

```python
from datetime import datetime

from sqlalchemy import DateTime, String, func
from sqlalchemy.orm import Mapped, mapped_column

from app.database import Base


class Post(Base):
    __tablename__ = "posts"

    id: Mapped[int] = mapped_column(primary_key=True, index=True)
    title: Mapped[str] = mapped_column(String(200))
    description: Mapped[str]
    author: Mapped[str] = mapped_column(String(100))
    created_at: Mapped[datetime] = mapped_column(
        DateTime,
        server_default=func.now(),
    )
```

### SQLAlchemy Mapping

| Attribute | Description |
|-----------|-------------|
| `__tablename__` | Database table name |
| `Mapped[]` | Python type of the column |
| `mapped_column()` | Creates a database column |
| `primary_key=True` | Primary key |
| `index=True` | Creates a database index |
| `server_default=func.now()` | Stores the current timestamp |

### Key Points

- Each SQLAlchemy model represents a database table.
- Each class attribute represents a table column.
- `Mapped[]` defines the Python data type.
- `mapped_column()` defines the database column.
- `Base` enables SQLAlchemy ORM mapping.

## Phase 7 - Dependency Injection

### Objective

Create a reusable database dependency that provides a database session to the Repository layer.

### Why Dependency Injection?

Without Dependency Injection, every API endpoint or repository would need to create and close its own database session.

With Dependency Injection, FastAPI creates the session, provides it where needed, and automatically closes it after the request is completed.

### Step 1 - Create the Database Dependency

**File:** `app/dependencies.py`

```python

from app.database import SessionLocal


def get_db():
    db = SessionLocal()

    try:
        yield db
    finally:
        db.close()
```

### How It Works

```text
Client Request
      │
      ▼
FastAPI
      │
      ▼
get_db()
      │
      ▼
SessionLocal()
      │
      ▼
Database Session
      │
      ▼
Repository
      │
      ▼
Database
      │
      ▼
db.close()
```

### Components

| Component | Purpose |
|----------|---------|
| `SessionLocal()` | Creates a database session |
| `yield` | Provides the session to FastAPI |
| `finally` | Ensures the session is always closed |
| `Generator` | Specifies that the function yields a value before cleanup |

### Key Points

- A new database session is created for each request.
- The same session is shared throughout the request.
- FastAPI automatically closes the session after the request is completed.
- Database sessions should always be obtained through `get_db()`.

```python
    self,
    db_post: Post,
    post: PostPatchUpdate,
```

**File:** `app/repositories/post_repository.py`

```python
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models import Post
from app.schemas import (
    PostCreate,
    PostPutUpdate,
    PostPatchUpdate,
)


class PostRepository:

    def __init__(self, db: Session):
        self.db = db

    def create(self, post: PostCreate) -> Post:
        db_post = Post(**post.model_dump())

        self.db.add(db_post)
        self.db.commit()
        self.db.refresh(db_post)

        return db_post

    def get_all(self) -> list[Post]:
        stmt = select(Post)

        return self.db.execute(stmt).scalars().all()

    def get_by_id(self, post_id: int) -> Post | None:
        return self.db.get(Post, post_id)

    def replace(
        self,
        db_post: Post,
        post: PostPutUpdate,
    ) -> Post:

        db_post.title = post.title
        db_post.description = post.description
        db_post.author = post.author

        self.db.commit()
        self.db.refresh(db_post)

        return db_post

    def update(
        self,
        db_post: Post,
        post: PostPatchUpdate,
    ) -> Post:

        for key, value in post.model_dump(exclude_unset=True).items():
            setattr(db_post, key, value)

        self.db.commit()
        self.db.refresh(db_post)

        return db_post

    def delete(self, db_post: Post) -> None:
        self.db.delete(db_post)
        self.db.commit()
```

### Key Points

- The Repository layer contains only database operations.
- `Session.get()` retrieves a record using its primary key.
- `execute().scalars().all()` retrieves ORM objects from a query.
- The Service layer retrieves the entity before calling `replace()` or `update()`.
- `exclude_unset=True` updates only the supplied fields.
- `setattr()` dynamically updates object attributes.

### Complete File

**File:** `app/exception_handlers.py`

```python
from fastapi import FastAPI, HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from starlette.exceptions import HTTPException as StarletteHTTPException

from app.exceptions import PostException
```


```python
def register_exception_handlers(app: FastAPI):
```

```python
    @app.exception_handler(PostException)
    async def post_exception_handler(request: Request, exc: PostException):
        return JSONResponse(
            status_code=exc.status_code,
            content={"message": str(exc)},
        )
```

```python
    @app.exception_handler(StarletteHTTPException)
    async def starlette_http_exception_handler(request: Request, exc: StarletteHTTPException):
        return JSONResponse(
            status_code=exc.status_code,
            content={"message": exc.detail},
        )
```

```python
    @app.exception_handler(HTTPException)
    async def fastapi_http_exception_handler(request: Request, exc: HTTPException):
        return JSONResponse(
            status_code=exc.status_code,
            content={"message": exc.detail},
        )
```

```python
    @app.exception_handler(RequestValidationError)
    async def validation_exception_handler(request: Request, exc: RequestValidationError):
        return JSONResponse(
            status_code=422,
            content={
                "message": "Validation failed.",
                "errors": exc.errors(),
            },
        )
```

```python
    @app.exception_handler(Exception)
    async def general_exception_handler(request: Request, exc: Exception):
        return JSONResponse(
            status_code=500,
            content={"message": "Internal Server Error."},
        )
```

### Step 10 - Apply the Migration

The new column is added without affecting existing data.

### Step 11 - Roll Back a Migration

Rollback one migration.

### Key Points

- Alembic manages database schema changes.
- Each migration is stored as a versioned Python script.

- `downgrade` rolls back migrations.
- Production applications should use Alembic instead of `Base.metadata.create_all()`.
