## 1. Class vs. Instance Members

* **Instance Members**: Bound to individual class objects. Created inside `__init__`.
* **Class Members**: Shared across all instances of a class. Declared directly inside the class body.
* **Class Methods (`@classmethod`)**: Access and modify class-level state.
* **Static Methods (`@staticmethod`)**: Utilities attached to classes containing no references to instance/class states.

```python
class Student:
    school_name = "Tech University"  # Class Attribute

    def __init__(self, name: str):
        self.name = name  # Instance Attribute

    @classmethod
    def change_school(cls, new_name: str):
        cls.school_name = new_name

    @staticmethod
    def is_valid_age(age: int) -> bool:
        return age >= 18
```

## 2. Dunder (Magic) Methods

Dunder (Double Under) methods allow user-defined classes to hook into built-in operators and protocols.

```python
class Vector:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    # String representation (Developer view)
    def __repr__(self) -> str:
        return f"Vector({self.x}, {self.y})"

    # Addition operator (+)
    def __add__(self, other: "Vector") -> "Vector":
        return Vector(self.x + other.x, self.y + other.y)

    # Equality check (==)
    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Vector):
            return False
        return self.x == other.x and self.y == other.y

v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)  # Vector(4.0, 6.0)
```

## 3. Abstract Base Classes (ABC)

Abstract Base Classes define common interfaces/contracts that subclasses must implement.

```python
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    @abstractmethod
    def process_payment(self, amount: float) -> bool:
        pass

class StripePayment(PaymentGateway):
    def process_payment(self, amount: float) -> bool:
        print(f"Processing ${amount} via Stripe.")
        return True

# StripePayment() operates correctly
# PaymentGateway() cannot be instantiated (raises TypeError)
```

## 4. Multiple Inheritance and Method Resolution Order (MRO)

Python resolves method names in multiple inheritance trees using C3 Linearization. You can inspect the ordering using the `__mro__` attribute.

```python
class A:
    def greet(self):
        print("Hello from A")

class B(A):
    def greet(self):
        print("Hello from B")

class C(A):
    def greet(self):
        print("Hello from C")

class D(B, C):
    pass

d = D()
d.greet()  # Prints: "Hello from B"
print(D.__mro__)  # (D, B, C, A, object)
```

### Exercise 1: Custom Collection Class
Create a class `BookShelf` that stores a list of books. Implement the dunder methods `__len__` (returns the count of books) and `__getitem__` (allows slicing/indexing shelves directly, e.g. `shelf[0]`).

<Accordion title="Click to view solution">
```python
class BookShelf:
    def __init__(self, books=None):
        self.books = books if books is not None else []

    def add_book(self, title: str):
        self.books.append(title)

    def __len__(self) -> int:
        return len(self.books)

    def __getitem__(self, index):
        return self.books[index]

# Usage:
```

### Exercise 2: Abstract Storage Interface
Create an Abstract Base Class `StorageEngine` defining two abstract methods: `save(self, key: str, data: str)` and `load(self, key: str) -> str`. Implement a concrete class `LocalStorage` using standard python dictionaries to emulate file storage.

<Accordion title="Click to view solution">
```python
from abc import ABC, abstractmethod

class StorageEngine(ABC):
    @abstractmethod
    def save(self, key: str, data: str) -> None:
        pass

    @abstractmethod
    def load(self, key: str) -> str:
        pass

class LocalStorage(StorageEngine):
    def __init__(self):
        self.db = {}

    def save(self, key: str, data: str) -> None:
        self.db[key] = data

    def load(self, key: str) -> str:
        return self.db.get(key, "")
```
