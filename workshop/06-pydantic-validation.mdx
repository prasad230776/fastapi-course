# Module 6: Data Validation with Pydantic

Configure robust runtime data validation, custom validation rules, type-coercion, and schema serialization.

---

## 1. Creating Pydantic Models

Pydantic models declare structural schemas. When instantiation occurs, Pydantic parses values, performing coercion where possible (e.g. converting string `"42"` into integer `42`).

```python
from pydantic import BaseModel, EmailStr, Field

class UserSchema(BaseModel):
    id: int
    name: str = Field(min_length=2, max_length=50)
    email: EmailStr
    is_active: bool = True
```

---

## 2. Advanced Validators

Custom validator hooks (`@field_validator` and `@model_validator`) permit advanced validation logic and cross-field checking.

```python
from pydantic import BaseModel, field_validator, model_validator

class ProjectSubmission(BaseModel):
    title: str
    score: int
    feedback: str = ""

    # Field-level validator
    @field_validator("score")
    @classmethod
    def validate_score(cls, value: int) -> int:
        if not (0 <= value <= 100):
            raise ValueError("Score must be between 0 and 100.")
        return value

    # Model-level validator (cross-field validation)
    @model_validator(mode="after")
    def check_feedback(self) -> "ProjectSubmission":
        if self.score < 50 and not self.feedback:
            raise ValueError("Feedback must be provided for failing scores.")
        return self
```

---

## 3. Serialization and Deserialization

* **Deserialization**: Parse raw JSON string or dictionaries into Pydantic models.
* **Serialization**: Export Pydantic objects back to JSON strings or python dictionaries.

```python
raw_data = {"id": 1, "name": "Jane", "email": "jane@example.com"}

# 1. Deserialization
user = UserSchema.model_validate(raw_data)

# 2. Serialization to Dict
user_dict = user.model_dump()

# 3. Serialization to JSON String
user_json = user.model_dump_json()
```

### Exercise 1: Event Registration Schema
Build a Pydantic model `EventRegistration` containing a username, email, phone number, and a seat count. Configure the model so that if seat count is less than 1 or greater than 5, a validation error is thrown.

<Accordion title="Click to view solution">
```python
from pydantic import BaseModel, EmailStr, Field, field_validator

class EventRegistration(BaseModel):
    username: str
    email: EmailStr
    phone: str
    seats: int = Field(default=1)

    @field_validator("seats")
    @classmethod
    def validate_seats(cls, value: int) -> int:
        if not (1 <= value <= 5):
            raise ValueError("You can reserve between 1 and 5 seats only.")
        return value
```

### Exercise 2: Date Range Validator
Define a Pydantic model `DateRange` containing a `start_date` and `end_date`. Implement a model-level validator verifying that `end_date` occurs after `start_date`.

<Accordion title="Click to view solution">
```python
from datetime import date
from pydantic import BaseModel, model_validator

class DateRange(BaseModel):
    start_date: date
    end_date: date

    @model_validator(mode="after")
    def validate_dates(self) -> "DateRange":
        if self.end_date <= self.start_date:
            raise ValueError("End date must be chronologically after the start date.")
        return self
```
