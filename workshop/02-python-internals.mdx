# Mutability and Immutability

## Objects and Object Identity

Everything in Python is an object.

Variables do **not** store values directly. Instead, they store **references to objects**.

Python provides the `id()` function to view the unique identity of an object.

```python
language = "Python"

print(id(language))
```

<Accordion title="Show Output">

```text
140521723456784
```

</Accordion>

Assigning another variable doesn't create a new object.

```python
language = "Python"
another = language

print(id(language))
print(id(another))
```

<Accordion title="Show Output">

```text
140521723456784
140521723456784
```

</Accordion>

Both variables refer to the same object.

## Immutable Objects

An immutable object **cannot be modified** after it is created.

Instead, Python creates a new object whenever its value changes.

Strings are immutable.

```python
text = "Python"

print(id(text))

text += " 3"

print(id(text))
```

<Accordion title="Show Output">

```text
140521723456784
140521723457040
```

</Accordion>

Notice that the memory address changes because a **new string object** is created.

Common immutable types include:

- int
- float
- bool
- str
- tuple
- frozenset

---

## Mutable Objects

Mutable objects **can be modified without creating a new object**.

```python
numbers = [10, 20]

print(id(numbers))

numbers.append(30)

print(id(numbers))
```

<Accordion title="Show Output">

```text
140521715623424
140521715623424
```

</Accordion>

The memory address remains the same because the existing object is modified.

Common mutable types include:

- list
- dict
- set

## Assignment vs Modification

Both variables reference the same list.

## Mutable Default Argument Pitfall

One common mistake is using mutable objects as default parameter values.

```python
def add_item(item, items=[]):
    items.append(item)
    return items

print(add_item("Python"))
print(add_item("FastAPI"))
```

<Accordion title="Show Output">

```text
['Python']
['Python', 'FastAPI']
```

</Accordion>

The default list is created only once and reused in every function call.

### Correct Approach

Use `None` as the default value.

```python
def add_item(item, items=None):
    if items is None:
        items = []

    items.append(item)

    return items

print(add_item("Python"))
print(add_item("FastAPI"))
```

<Accordion title="Show Output">

```text
['Python']
['FastAPI']
```

</Accordion>


<Accordion title="Solution">

```python

    return names

```

</Accordion>


# Variable Scope

Variables are only accessible within the region where they are defined. This visibility is known as **scope**.

Python resolves variable names using the **LEGB Rule**, but before learning the rule, let's understand the different scopes.

## Local Scope

A variable created inside a function is called a **local variable**.

```python

    message = "Hello"

    print(message)

greet()
```

<Accordion title="Show Output">

```text
Hello
```

</Accordion>

Trying to access a local variable outside the function results in an error.

```python
# print(message)
```

## Global Scope

Variables created outside all functions belong to the global scope.


</Accordion>

A function can read global variables without any special keyword.

## The `global` Keyword

A function can **read** a global variable without any special keyword.

However, to **modify** a global variable inside a function, Python requires the `global` keyword.

Without the `global` keyword, Python assumes `count` is a local variable and raises an error.

## The `nonlocal` Keyword

If the inner function needs to modify a variable from the enclosing function, use the `nonlocal` keyword.

```python
def outer():
    count = 0

    def inner():
        nonlocal count
        count += 1
        print(count)

    inner()

outer()
```

<Accordion title="Show Output">

```text
1
```

</Accordion>

Without `nonlocal`, Python treats `count` as a new local variable.

# LEGB Rule

Whenever Python encounters a variable, it searches for it in the following order:

| Scope | Description |
|--------|-------------|
| **L** | Local |
| **E** | Enclosing |
| **G** | Global |
| **B** | Built-in |

Python stops searching as soon as it finds the variable.

### Local Scope

```python
message = "Global"

def display():
    message = "Local"
    print(message)

display()
```

<Accordion title="Show Output">

```text
Local
```

</Accordion>

Python first checks the **Local** scope.

---

### Enclosing Scope

```python
def outer():
    message = "Outer"

    def inner():
        print(message)

    inner()

outer()
```

<Accordion title="Show Output">

```text
Outer
```

</Accordion>

If the variable isn't found locally, Python checks the enclosing function.

---

### Global Scope

```python
message = "Global"

def display():
    print(message)

display()
```

<Accordion title="Show Output">

```text
Global
```

</Accordion>

If Python doesn't find the variable in the local or enclosing scope, it searches the global scope.

---

### Built-in Scope

Finally, Python searches its built-in names.

```python
print(len("Python"))
```

<Accordion title="Show Output">

```text
6
```

</Accordion>

`len()` is a built-in function.

---

### Remembering LEGB

Python searches variables in this order:

```text
Local
   ↓
Enclosing
   ↓
Global
   ↓
Built-in
```

Once a variable is found, Python stops searching.

---

## Scope Recap

Before learning closures, let's quickly recap variable scope.

- **Local** variables belong to the current function.
- **Global** variables belong to the entire program.
- **Enclosing** variables belong to an outer function.
- The `global` keyword modifies global variables.
- The `nonlocal` keyword modifies variables in the enclosing function.
- Python resolves variable names using the **LEGB Rule**.

Closures build directly on the concept of **nested functions** and the **enclosing scope**.

---

# Closures

A **closure** is a function that remembers the variables from its enclosing scope even after the outer function has finished executing.

Closures are useful for preserving state without using global variables.

## Nested Functions

Python allows defining one function inside another function.

```python
def outer():
    message = "Hello"

    def inner():
        print(message)

    inner()

outer()
```

<Accordion title="Show Output">

```text
Hello
```

</Accordion>

The inner function can access variables from the outer function.

---

## Returning a Function

A function can also return another function.

```python
def outer():
    message = "Hello"

    def inner():
        print(message)

    return inner

greet = outer()

greet()
```

<Accordion title="Show Output">

```text
Hello
```

</Accordion>

Although `outer()` has already finished executing, `inner()` still remembers the value of `message`.

This behavior is called a **closure**.

---

## Practical Example

Suppose we want to greet users in different languages.

```python
def greeting(language):

    def greet(name):
        print(f"{language}, {name}!")

    return greet

english = greeting("Hello")
spanish = greeting("Hola")

english("Alice")
spanish("Bob")
```

<Accordion title="Show Output">

```text
Hello, Alice!
Hola, Bob!
```

</Accordion>

Each returned function remembers its own value of `language`.

# Decorators

A decorator allows us to **add extra functionality to a function without modifying the function itself**.

Decorators are commonly used for logging, authentication, validation, caching, and timing functions.

## A Simple Decorator

```python
def logger(func):

    def wrapper():
        print("Function started")

        func()

        print("Function finished")

    return wrapper


@logger
def greet():
    print("Hello!")

greet()
```

<Accordion title="Show Output">

```text
Function started
Hello!
Function finished
```

</Accordion>

The `@logger` line automatically wraps the `greet()` function with additional behavior.

---

## Decorator with Parameters

Functions often accept arguments.

```python
def logger(func):

    def wrapper(name):
        print("Starting...")

        func(name)

        print("Completed.")

    return wrapper


@logger
def greet(name):
    print(f"Hello {name}")

greet("Alice")
```

<Accordion title="Show Output">

```text
Starting...
Hello Alice
Completed.
```

</Accordion>

---

## Practical Example

Count how many times a function is executed.

```python
def counter(func):

    count = 0

    def wrapper():

        nonlocal count

        count += 1

        print(f"Called {count} time(s).")

        func()

    return wrapper


@counter
def hello():
    print("Hello")

hello()
hello()
hello()
```

<Accordion title="Show Output">

```text

Hello
Called 2 time(s).
Hello
Called 3 time(s).
Hello
```

</Accordion>

# Context Managers

Whenever we open external resources such as files or database connections, they should be closed properly.

Python provides the **with** statement to handle this automatically.

---

## Without a Context Manager

```python
file = open("sample.txt", "r")

content = file.read()

print(content)

file.close()
```

If an exception occurs before `close()`, the file may remain open.

---

## Using a Context Manager

```python
with open("sample.txt", "r") as file:

    content = file.read()

    print(content)
```

The file is automatically closed after leaving the `with` block.

---

## Custom Context Manager

A context manager implements two special methods.

- `__enter__()`
- `__exit__()`

```python
class Database:

    def __enter__(self):
        print("Connection Opened")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Connection Closed")


with Database():
    print("Executing Queries")
```

<Accordion title="Show Output">

```text
Connection Opened
Executing Queries
Connection Closed
```

</Accordion>
